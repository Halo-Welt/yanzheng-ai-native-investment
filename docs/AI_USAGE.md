# AI 使用与验证记录

本文件记录本次开发中实际发生的AI参与、主Agent整合与修正，不能替代候选人自己的理解与复核。用户明确要求多子Agent完成任务，并补充希望界面主题接近同花顺。

## 工具与责任

| 工具/角色 | 实际参与 | 最终责任 |
| --- | --- | --- |
| Codex 主Agent | 阅读题目、选择边界、定义接口、依赖与构建、部署、真实调用与最终验收 | 汇总证据，修正不一致，报告未完成项 |
| 产品与数据子Agent | 检索年报、逐字段取数、产品方案、指标和演示脚本；第二轮独立对抗验收 | 来源与日期可复核；未获得的能力不得声称接通 |
| 后端子Agent | DeepSeek适配、受限证据检索、计算、人机边界、异常和自动测试 | 确定性校验兜底，不能只相信模型返回 |
| 前端子Agent | React工作台、证据抽屉、复核/备注/导出/历史与响应式主题 | 真交互，无静态截图冒充产品 |
| Image Gen | 初版绿色主题完整主屏概念图 | 参考布局；文字、数据、控件全部代码实现 |
| DeepSeek API | 运行时把研究文稿拆成结构化主张 | 输出经过原文定位、字段、年份、单位、数值与风险校验 |
| Playwright CLI | 浏览器操作、截图、主链路验收 | 检查实际渲染；不以build成功代替用户流程 |

内置Browser技能需要的browser-client.mjs在当前安装目录缺失，已按要求报告并采用Playwright替代。红色改版概念图生成遇网络失败，实施依据为初版布局与用户明确给出的同花顺主题偏好；不伪造第二张成功概念图。

## 实际产品推理流程

模型做语义提取，输出原文连续片段与字段线索。程序校验结构和原文定位，随后执行 `retrieve_evidence`、`verify_numeric`、`compare_growth` 与 `guard_compliance`。本产品没有声称模型自主联网或自主挑选工具。用户可以查看每一步的实际返回及耗时；执行记录不是预设动画。

`mode:live` 只对应真实DeepSeek调用，密钥、鉴权、余额、网络或输出异常必须返回失败。`mode:demo` 需用户显式选择，返回 `modelCalls:0` 及醒目标识。

## 已发生的修正

1. **收入口径**：公开年报核对发现营业收入1708.99亿元/+15.71%，营业总收入1741.44亿元/+15.66%是不同口径。字段分开保存，禁止相互替代。
2. **概念图页码**：图像生成把证据页码写为第9页。原始PDF主要财务指标实际在第5页，产品使用真实页码；营业总收入在第8页。
3. **增速比较**：早期语义分类只会把比较句标为推断。加入确定性比较后，“利润增速高于营收增速”显示与15.38%和15.71%的原始字段冲突，差值-0.33个百分点。
4. **原文定位**：模型提供的数字和单位不能仅因出现在同一段就通过。核验需验证原文、统计口径与期间，防止错映射。
5. **HTTP成功不等于业务成功**：扶摇匿名请求返回HTTP200但业务码2003/缺少API Key，交付记录明确为未接通，而不是成功取数。
6. **主题偏好**：用户补充同花顺考试背景，主色改为红#d93036，白底深灰字；未使用官方商标或冒充官方产品。
7. **独立挑战**：第二轮验收复现时点混用、多公司上下文误归属、字段数值交叉绑定以及部分风险同义表达漏检，先写回归用例再修复。修复后结果见TESTING，不把规则覆盖夸大为完整合规能力。

## 已保存的真实调用

`docs/live-audit.json` 为第一次真实模型调用的完整结构化结果，仅包含构造摘要与公开年报字段，不含凭证。

- 模型：`deepseek-flash`，一次语义提取。
- 输入：贵州茅台2024年度混合测试摘要，包含正确事实、错误比较、待证推断与禁止表达。
- 工程耗时：1757ms；供应商返回总token 630。
- 返回8条主张：4支持、1冲突、1推断、2禁止。
- 解释：一次样例技术验证，不能当作总体准确率、业务效率或投资能力。

模型后续输出可能不同。自动测试中的mock extractor只用于可重复验证异常分支，不能记为真实AI调用。

## 第二条真实模型与规则对照

输入：`贵州茅台2024年营收1708.99亿元，较上年增加15.71%。`

- 规则演示：1条无法核验，未映射出有效字段。
- DeepSeek：2条数值事实分别映射营业收入和收入同比，2条均有同口径原始证据。
- 真实调用1233ms、381 tokens；全量两模式结果见 `docs/live-semantic-comparison.json`。

这个样例展示AI处理指标简称和改写表达的增量，只有一条输入，不可据此得出总体优于规则的准确率结论。后续需要独立标注集对照。

## 集成阶段修正与验收

主Agent在实际HTTP集成发现Vite代理来源头不一致导致403，修正转发原始Host后验证成功。新增4项导出回归，捕获重复PDF页码锚点并修复。历史恢复调整为在内存保存原始摘要快照，只有明确启用本机保存后才持久化；提示明确包括摘要原文，恢复后可继续复核。默认不持久化。

浏览器另外两次真实混合摘要调用均成功；最终一次结果及人工备注见browser-audit.json（一次模型调用、8条主张、4支持/1冲突/1推断/2禁止）。目前本地共完成4次真实API调用：混合初验、语义对照和两次浏览器主链路。后续线上验证另行记录，不与mock混淆。
