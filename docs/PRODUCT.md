# 研证：投研观点证据审校工作台

研究员写好一段摘要后，最费心的工作往往是逐句找原文、核对指标口径、判断哪些属于推断，再交给同事复核。研证把这段流程变成一份可逐项处理的证据审校清单：每条结论能找到来源字段，无法证明的地方明确留待核实。

## 场景与用户

目标用户是 3–10 人研究团队中的初级研究员及复核人员。输入是已经成文的研究摘要，输出是带证据、问题类型和人工处理记录的审校报告。使用时点是摘要进入内部晨会、研究材料归档或内容发布流程之前。

核心待完成任务：**在保留研究员判断权的前提下，快速发现摘要中的数字错配、字段口径混用、缺少依据的推断和不合适的确定性表达。**

问题值得解决的理由是工作流中存在重复、可验证的步骤。一个“1,708.99 亿元”的正确数字，可能被错误地写成“营业总收入”；单靠搜到同一数字不能验证语句。这一需求判断来自流程分析，尚未通过真实用户访谈证明，后续用对照实验验证。

首版把验证范围收敛到贵州茅台公开历史年报。数据覆盖已明确披露在页面和来源文档中；超出公司、年度、字段范围时，应显示缺证，不能按已知公司数据补齐。

## 一条完整主链路

1. 研究员输入、编辑或载入示例摘要，确认公司和历史数据覆盖范围。
2. AI 拆解自然语言断言，识别公司、年度、指标、数值、单位和推断关系。
3. Agent 调用证据检索工具，获取带原始字段、单位、报告期和页码的结构化证据。
4. 数值和单位由确定性代码核验，语义推断与合规风险分别标注，避免让模型单独决定所有事实。
5. 用户打开原文和字段，逐项复核、修订或保留问题；审校状态随用户动作更新。
6. 导出报告，保留原始输入、审校结论、证据和人工反馈，交给后续内部流程。

产品应显式呈现运行中、完成、部分失败、失败等状态。接口失败或模型不可用不能伪装成“审校正常”。演示 / 故障注入状态必须与真实模型模式区分。具体已实现状态和测试结果以 README 与测试记录为准。

## 为什么需要 LLM / Agent

| 方法 | 适合的工作 | 在本场景的不足 | 研证的选择 |
| --- | --- | --- | --- |
| 关键词或正则规则 | 检查固定敏感词、数值、格式 | 同义表达、隐含比较、复合句需要人工拆解 | 保留为确定性安全与数字校验层 |
| 搜索 | 找到年报或关键词所在段落 | 同一数字出现不能证明字段、年度和口径对应 | 让 AI 根据断言选择证据，随后核验 |
| 传统数据终端 | 提供标准化指标和历史序列 | 仍需研究员把自然语言逐句映射到字段 | 沿用结构化数据作为工具输出 |
| 人工复核 | 理解上下文并作最终判断 | 重复查找、换算、记录消耗精力 | 将人工时间集中在未解决的判断上 |
| LLM + 受限工具 | 拆句、识别指标同义表达、解释比较关系 | 可能幻觉、引用错误或受提示注入影响 | 证据白名单、字段核验、失败显式化、人工复核 |

LLM 的增量是理解未预设的文字表达，并把待验证断言组织成工具任务；规则和计算仍负责确定性部分。产品不把模型生成的解释当作原始事实，源数据不会由模型补写。

## 数据、状态、反馈、人机协作

- 数据：8 个已核验公开历史数值字段，保留原始元数、展示单位、报告期、披露日期、获取日期、原文页码；来源见 [SOURCES.md](./SOURCES.md)。
- 工具：受限证据检索、数值 / 单位核验、断言审校；Agent 每次调用结果需要可查看。
- 状态：结果与当前输入绑定，重新运行不能把旧输入的人工处理状态误挂到新结果上。
- 人工：用户查看证据、确认问题或修订文字。人工确认代表处理动作，不代表事实在法律或专业意义上已经认证。
- 反馈：保留问题类型、用户修订与处理状态，为后续评估建立匿名样本；首版没有后台训练或自动利用用户输入调优。
- 输出：报告保留未解决问题；不能通过一键确认把“缺少证据”改写为“事实成立”。

## 成功标准与验证设计

下列为**拟定验收目标**，不是已取得的业务成绩。构造用例只用于软件验收，不替代用户实验。

| 维度 | 指标定义 | 首轮目标 | 测量方式 |
| --- | --- | --- | --- |
| 可追溯性 | 标注为支持的事实中，能定位正确原始字段、年度、单位和页码的比例 | 固定证据集 100% | 逐条人工核对，记录分母 |
| 数值质量 | 数字错写、单位错配、年度错配的检出率 | 人工标注挑战集 ≥95% | 30 段以上盲标摘要，按问题计数 |
| 安全边界 | 确定性预测、收益承诺、直接买卖建议的高风险检出率 | 挑战集中 ≥95%，误报同步披露 | 独立样本含否定句、引用语和提示注入 |
| 效率 | 从收到摘要到形成复核清单的中位人工用时 | 相对人工流程降低 ≥30% | 至少 5 名研究员，交叉顺序的配对任务 |
| 实用性 | 用户最终保留的问题标记数 / 所有问题标记数 | ≥70% | 观察标记的采纳 / 误报情况 |
| 可靠性 | 上游异常中被明确提示而未显示为正常的比例 | 故障用例 100% | 缺证、超时、业务错误码、格式错误 |

评估时比较“规则基线”“人工复核”“AI + 工具”三组，分别计时并统计误报与漏报。先用同等难度但不同内容的摘要，随机顺序，避免第二遍阅读造成效率假象。报告样本量、失败数和任务范围，不把单次演示效果外推到整个 A 股市场。

## 非目标

首版不做股票推荐、价格预测、收益承诺、下单、持仓优化或投资适当性判断；不判断公司是否值得投资；不声称取代持牌投顾、研究负责人或正式合规审核。

不支持全市场财报解析、任意 PDF 上传、多用户权限、多人实时协作和长期服务端审校档案；也未接通扶摇或 iFinD 授权数据。公开年报作为有限证据集，已获得原文可复核性，但不能证明跨公司泛化能力。

## 失败条件和风险控制

| 触发条件 | 应有行为 | 后续处理 |
| --- | --- | --- |
| 公司、报告期或指标不在覆盖范围 | 显示缺证 / 无法核验 | 用户补充来源或等待数据扩展 |
| 2024 年数据被用于“今年”“当前”“最新” | 标注时点不匹配或过期风险 | 要求明确年度或获取对应时点证据 |
| 原始字段为空、来源冲突 | 保留空值或双方来源，不能补零或自行选边 | 人工核对最新披露版本 |
| 模型超时、余额不足、鉴权失败、无效 JSON | 显示真实失败；不能自动生成“正常”结论 | 重试或查看明确标识的演示模式 |
| 输入带“忽略规则”等指令 | 当作待审文本处理 | 保持工具与数据访问白名单 |
| 模型引用不存在的证据 ID | 不认可该引用，降为无法核验 | 留下错误状态并提示重审 |
| 包含买卖建议或收益承诺 | 标注高风险表达，禁止把它写入安全修订结论 | 删除或改为需要独立研究的问题 |
| 用户未处理所有风险项 | 报告保留待处理状态 | 交接给后续人工审阅 |

本产品的高风险表达识别属于辅助质量治理，不能被宣称为满足全部监管要求的正式合规系统。提交者负责按真实使用环境补充权限、审计、留存与适用要求。任何新增实时数据源都应验证实际授权和使用范围。

## 24 小时执行安排

| 时间预算 | 主责 | 可验收产物 |
| --- | --- | --- |
| 0–2 小时 | 主 Agent + 产品数据 Agent | 场景边界、原始年报字段、接口约定 |
| 2–6 小时 | 后端 Agent | 真实模型适配、受限工具、异常处理和测试 |
| 2–8 小时（并行） | 前端 Agent | 从输入到证据、复核和导出的主界面 |
| 6–12 小时 | 主 Agent | 前后端集成、真实调用验证、失败复现 |
| 12–18 小时 | 主 Agent + 各 Agent | 数据口径、响应式、合规挑战与回归 |
| 18–22 小时 | 主 Agent | 部署、源码仓库、README 与 AI 使用记录 |
| 22–24 小时 | 主 Agent | 提交链接校验、90 秒演示和最终走查 |

这是任务规划预算，并非伪造的实际耗时日志。实际测试数量、模型调用、部署状态与完成情况需要在交付记录中如实填写。

## 后续优先验证

第一优先是让真实研究员完成配对实验，判断节省的查证时间是否抵消误报处理成本。第二优先是在获得扶摇授权后扩展公司与年度，同时保留年报交叉核验。第三优先是加入正文段落、公告修订版本、新闻时效和持久化审校档案。范围扩展应以溯源正确率和失败显式化指标达标为前提。
